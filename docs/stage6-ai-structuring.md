## 1. Поток

```mermaid
sequenceDiagram
  participant C as Клиент
  participant S as Сервер
  participant G as Gemini
  C->>C: дописать текст, отправить очередь (sync)
  C->>S: POST /ai/structure {node_id, source_revision}
  S-->>C: 202 {request_id}; узел → «структурируется…»
  S->>G: системный промпт v1 + данные в разделителях (JSON-ответ по схеме)
  G-->>S: role, facts, constraints, open_questions, formatted_text
  S->>S: валидатор
  alt нарушений нет и исходник не менялся
    S->>S: применить: старая структура → версия before_structure
  else исходник изменился, пока ИИ работал
    S->>S: сохранить как предложение (не применять)
  else валидатор нашёл нарушения
    S->>S: сохранить как предложение с замечаниями
  end
  S-->>C: WebSocket «есть ревизия» → pull
```

Запрос асинхронный: клиент может закрыть приложение, результат придёт при следующей синхронизации. Очередь — в процессе сервера, 2 обработчика; при перезапуске сервера незавершённые запросы ставятся заново.

## 2. Данные

`structured_content` (jsonb):

| Поле | Что это |
|---|---|
| `role` | роль для Claude («Act as a Senior …»), разрешённое служебное поле |
| `facts`, `constraints`, `open_questions` | ответ модели по схеме |
| `formatted_text` | итоговый текст задачи (без роли); его правит пользователь |
| `ai_formatted_text` | последняя версия от ИИ — чтобы отличать правки человека |
| `human_paragraphs` | абзацы, написанные или изменённые человеком; ИИ их не трогает |
| `source_raw` | исходник, из которого получен результат — для дельты при повторе |

`node_content.structure_proposal` — результат, который **не применён**: `{request_id, reason: stale | flagged | failed, source_revision, generated, findings, error}`.

`ai.structure_requests` — журнал запросов: статус (`queued`, `running`, `applied`, `proposed`, `flagged`, `failed`, `superseded`), ревизия и хэш исходника, версия промпта, модель, ответ, замечания валидатора, число попыток.

## 3. Транзакционность (ТЗ п. 6.2)

Результат применяется под той же блокировкой записи, что и операции синхронизации. Если `raw_revision` узла уже не равна `source_revision` запроса, результат **не применяется**: он сохраняется как предложение, пользователь видит «Пока ИИ работал, исходник изменился» и выбирает: применить, структурировать заново или отклонить. Исходный текст ИИ не меняет никогда — это другое поле.

## 4. Повторное структурирование (ТЗ п. 6.1)

Модель получает: прежнюю структуру, дельту исходника (построчный diff от `source_raw` до текущего текста) и абзацы человека с требованием оставить их дословно. Сервер не полагается на модель: валидатор проверяет, что каждый абзац человека есть в ответе.

## 5. Защита от галлюцинаций и инъекций (ТЗ п. 6.5)

- Промпт — версионируемый файл `backend/internal/ai/prompts/structure_v1.md`; в запросе хранится `prompt_version`.
- Текст пользователя передаётся только как данные между разделителями `<<<USER_INPUT` / `USER_INPUT>>>`; сами разделители в тексте экранируются.
- Ответ — JSON по схеме (`responseSchema`), не свободный текст.
- **Валидатор** (детерминированный, без LLM) — замечание, если в ответе есть:
  - число, которого нет во входе;
  - латинский термин (технология, библиотека, сущность), которого нет во входе — так ловятся «додуманные» технологии;
  - потерянный абзац человека;
  - признаки инъекции (разделители, фрагменты системного промпта, «ignore previous instructions»);
  - текст, несоразмерно длиннее входа.
  Поле `role` проверке технологий не подлежит.
- Ответ с замечаниями не применяется автоматически: пользователь видит список и решает.
- Тесты: конвейер с имитацией модели (в том числе ответы-«галлюцинации» и ответы, выполнившие инъекцию), плюс eval-тесты против настоящего Gemini, которые запускаются только при заданном `GEMINI_API_KEY`.

## 6. Интерфейс (на согласование)

- У AI Task в редакторе переключатель **Исходник / Структура** (как в концепте v1).
- «Структурировать» сначала отправляет несохранённые правки, затем запускает запрос; кнопка показывает «Структурируется…». Без сервера кнопка неактивна.
- Вкладка «Структура»: строка роли и итоговый текст, который можно править (правки помечаются как человеческие).
- Плашка предложения: «Пока ИИ работал, исходник изменился» → Применить / Структурировать заново / Отклонить; «Проверка нашла расхождения с исходником» + список → Применить всё равно / Отклонить; ошибка → Повторить.
- «Скопировать задачу» копирует роль + итоговый текст; если структура устарела — спрашивает, что копировать: структуру или исходник.

## 7. Настройки сервера

`GEMINI_API_KEY` (только в `.env` на сервере), `GEMINI_BASE_URL` (только для тестов с имитацией API), `GEMINI_MODEL` (по умолчанию `gemini-2.5-flash`), `AI_DAILY_LIMIT` (запросов на пользователя в сутки, по умолчанию 200). Ошибки 429/5xx — до 3 повторов с паузой; таймаут ответа — 90 с.
