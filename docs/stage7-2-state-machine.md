# Этап 7.2: state machine, lease и aicrew-host

Статус: **реализовано** (кроме сетевого allowlist-прокси и окружения windows_user — этапы 7.5–7.6). Дата: 08.10.2026. Основа: ТЗ п. 7, 8.1–8.4, 8.7; [7.1](stage7-1-aicrew-architecture.md).

Результат этапа: AI Task из дерева можно отправить в AiCrew; служба на домашнем ПК берёт её с lease, создаёт worktree, запускает исполнителя, автокоммитит, гоняет проверку и докладывает факты. Слияние — этап 7.3, поэтому успешная задача останавливается в `MERGEABLE`.

## 1. Статусы и переходы (сервер — единственный, кто их меняет)

| Из | В | Кто инициирует |
|---|---|---|
| `QUEUED` | `CLAIMED` | воркер (атомарно: `FOR UPDATE SKIP LOCKED`, все зависимости `DONE`, `retry_after` прошёл) |
| `CLAIMED` | `IN_PROGRESS` | воркер: worktree создан, `base_commit` записан |
| `IN_PROGRESS` | `VERIFYING` | воркер: агент закончил, автокоммит сделан |
| `VERIFYING` | `LLM_REVIEW` | воркер: проверки зелёные |
| `LLM_REVIEW` | `MERGEABLE` | воркер (в 7.2 ревью пропускается с пометкой, полноценное — 7.4) |
| `MERGEABLE` → `MERGED` → `POST_MERGE_VERIFY` → `DONE` | | этап 7.3 |
| любой активный | `FAILED` | воркер (с классом ошибки) или сервер (истёк lease) |
| `FAILED` | `QUEUED` / `AWAITING_HUMAN` / `BLOCKED` / `REPLAN` | сервер по политике класса (п. 3) |
| любой нефинальный | `CANCELLING` | пользователь |
| `CANCELLING` | `CANCELLED` | воркер подтвердил остановку, сервер — если задача не взята или lease истёк |
| `AWAITING_HUMAN`, `BLOCKED` | `QUEUED` | пользователь («повторить») |

Финальные: `DONE`, `CANCELLED`. Узел PromptTree при отмене не удаляется, история сохраняется (ТЗ п. 8.3). Каждый переход пишется в `exec.task_events`.

Воркер подтверждает право на переход парой `worker_id` + номер попытки: чужой или устаревший воркер получает отказ.

## 2. Lease и heartbeat (ТЗ п. 8.2)

- При захвате: `lease_expires_at = now + 2 мин`. Воркер шлёт heartbeat каждые 30 с, каждый продлевает lease.
- Ответ на heartbeat сообщает `cancel_requested` — так отмена доходит до воркера.
- Фоновый сборщик на сервере каждые 15 с переводит задачи с истёкшим lease в `FAILED` (класс `ENVIRONMENT_FAILURE`, код `lease_expired`) и сразу применяет политику повтора. Выключили ПК — задача вернётся в очередь.
- При старте aicrew-host удаляет worktree задач, которые ему больше не принадлежат.

## 3. Ошибки и повторы (ТЗ п. 8.4)

| Класс | Политика |
|---|---|
| `RATE_LIMIT` | повтор через `retry_after` (из ответа провайдера, иначе 15 мин), попытка не тратится |
| `NETWORK_ERROR`, `TIMEOUT`, `ENVIRONMENT_FAILURE` | повтор через 1 мин |
| `BUILD_FAILURE`, `TEST_FAILURE`, `AGENT_ERROR`, `QA_REJECT` | повтор, пока попыток меньше `max_attempts` (3); прошлые попытки и их факты передаются следующему запуску |
| `AUTH_ERROR` | сразу `AWAITING_HUMAN` |
| `MERGE_CONFLICT` | `REPLAN` (этап 7.3) |
| попытки кончились | `AWAITING_HUMAN` |

## 4. Данные (схема `exec`)

`hosts` (хост = устройство пользователя, вход как у приложений), `workers` (тип, модель, окружение, heartbeat), `repositories` (проект PromptTree, хост, локальный путь, профиль проверки), `tasks` (узел, текст задачи на момент отправки, статус, lease, попытки, класс ошибки, бюджеты, `execution_env`), `task_dependencies`, `attempts` (base/result commit, exit-коды, изменённые файлы, расход, итог агента), `task_events`.

Текст задачи — снимок итоговой задачи (роль + структура или исходник) на момент отправки: правки в дереве после этого задачу не меняют.

## 5. aicrew-host

Go-сервис в `/aicrew`. Вход — как устройство пользователя (refresh-токен и токен Claude Code хранятся зашифрованными DPAPI). Цикл: регистрация → захват (каждые 10 с и сразу по сигналу WebSocket) → heartbeat → конвейер:

1. `git worktree add .aiworktrees/task-<id> -b aicrew/task-<id>` от `HEAD` основной ветки → `IN_PROGRESS` с `base_commit`.
2. `AgentProvider.Run` — Claude Code (`claude -p … --output-format stream-json`) в одноразовом контейнере с примонтированным worktree; таймаут `agent_runtime`.
3. Автокоммит, сбор фактов кодом (не моделью): `result_commit`, `diff --stat`, изменённые файлы → `VERIFYING`.
4. Профиль проверки репозитория (список команд argv, без оболочки) в том же образе → `LLM_REVIEW` → `MERGEABLE`, либо `FAILED` с классом.

Свои команды хост запускает только из allowlist (`git`, `docker`) и только как argv, без `sh -c` (ТЗ п. 12).

## 6. Тесты этапа

Атомарность `CLAIMED` (параллельный захват), все переходы таблицы (разрешённые и запрещённые), убитый воркер (lease истёк → повтор), исчерпание попыток, `AUTH_ERROR` → человек, отмена в каждом состоянии, зависимости DAG, чужой воркер; на хосте — worktree и автокоммит на настоящем git, уборка осиротевших worktree, отмена останавливает агента, сквозной прогон «сервер + хост + имитация агента» на репозитории-песочнице.
