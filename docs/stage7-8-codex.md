# Этап 7.8. Codex: второй исполнитель и перекрёстное ревью

Решение владельца, 18.10.2026: Codex (подписка ChatGPT) работает параллельно с Claude и проверяет его код. В окне «Отправить в AiCrew…» для «одной задачи» появляется выбор Claude / Codex.

## 1. Как подключается

- **Клиент — родной у OpenAI: `codex exec`.** Это то же правило, что для Claude: у каждого поставщика свой клиент, а для чужих моделей — наш переходник. Codex запускается в том же одноразовом контейнере, что и Claude Code. Внутри видны только worktree задачи и скиллы (только для чтения).
- **Вход делаете вы.** На ПК выполняете `codex login` и входите своим аккаунтом ChatGPT. Затем запускаете `aicrew-host set-codex-auth`: служба забирает `~/.codex/auth.json` и хранит его зашифрованным (DPAPI), как токен Claude.
  - На каждую попытку служба кладёт файл во временную папку и монтирует её в контейнер.
  - После попытки забирает обновлённый файл обратно (Codex сам продлевает вход) и удаляет папку.
  - В командную строку и журналы файл не попадает. Сам я его не трогаю и не вижу.
- **Запуск:** `codex exec --json --sandbox danger-full-access --skip-git-repo-check -`. Задание подаётся через stdin, ограничения даёт сам контейнер: только worktree, лимиты памяти и процессов.
- **Расход:** из событий `turn.completed` берутся токены (обычные, кешированные, на рассуждения). Стоимость для подписки — 0, учитываем токены.
- **Лимиты:** если у подписки кончился лимит, задача получает `RATE_LIMIT` и ждёт, как у Claude.

## 2. Исполнитель

- Исполнитель `codex` есть только у хоста, где сохранён вход. Без него задачи Codex этому хосту не выдаются.
- **Окно «Отправить в AiCrew…» → «Одной задачей»:** переключатель Claude / Codex, по умолчанию Claude.
- **Manager** видит Codex в списке исполнителей. Он может раскладывать независимые задачи между Claude и Codex, чтобы они шли одновременно.
- **Junior** по-прежнему только по контракту. Контракт и сборку может делать Claude или Codex.

## 3. Параллельная работа

Сейчас служба берёт одну задачу за раз (решение 7.1). Предлагаю так:

- **Две очереди на хосте.** Одна для Claude, другая для Codex. Каждая берёт только задачи своего исполнителя, так что два разных поставщика работают одновременно, каждый в пределах своих лимитов.
- **Слияние, откат и план Manager'а** — только в очереди Claude. Слияние в integration остаётся строго по одному, как сейчас.
- **Junior** запускается, только когда другие задачи не идут: локальной модели нужна вся видеокарта и часть памяти. История с синим экраном.
- **Память.** Перед стартом второй задачи служба проверяет свободную память (≥ 8 ГБ). Иначе вторая задача ждёт: два контейнера с Flutter, Chrome и система вместе тяжёлые.
- **Конфликты.** Две параллельные задачи могут править одно место. Это уже решено в 7.3: при конфликте слияния задача уходит на доработку.

## 4. Перекрёстное ревью

- **Tech Lead — исполнитель другого поставщика.**
  - Код Claude смотрит Codex, код Codex смотрит Claude.
  - Код Junior смотрит тот, кто писал контракт.
- **Logic QA остаётся на Gemini.** Это третий независимый взгляд, и он нужен всем задачам.
- **Включается флажком «+ Tech Lead»**, как сейчас. Manager ставит его сложным задачам.
- **Почему так:** модели разных компаний ошибаются по-разному и лучше ловят чужие ошибки, чем свои.

## 5. Что нужно от владельца

1. Утвердить параллельность (раздел 3) и перекрёстное ревью (раздел 4).
2. После сборки: `codex login` на ПК, затем `aicrew-host set-codex-auth`.

## Проверка

- **Тесты:** разбор событий `codex exec --json`, хранение и возврат входа, выдача задач по очередям, выбор ревьюера, окно отправки.
- **Вживую:**
  - одна задача Codex на полигоне;
  - одновременно одна задача Claude и одна Codex;
  - перекрёстное ревью на задаче с «+ Tech Lead».
