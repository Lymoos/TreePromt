# P0: базовые решения (этап 1)

Статус: **согласовано** (08.10.2026).

| # | Решение | Итог | Статус |
|---|---|---|---|
| 1 | Топология | **VPS:** Go backend + PostgreSQL. **Домашний ПК:** AiCrew (execution host): Claude Code, Ollama, локальные checkout репозиториев. **Клиенты:** телефон, ПК, веб. | VPS — решено Максимом |
| 1a | Связь домашнего ПК с VPS | Домашний ПК сам открывает исходящее соединение к VPS (WebSocket) и забирает задачи. Входящих портов на домашнем ПК нет, проброс в роутере не нужен. Когда ПК выключен, задачи ждут в очереди на VPS, по истечении lease возвращаются в очередь. | согласовано |
| 2 | Репозитории | Каждое приложение — в своём репозитории. Проект содержит `repositories[]`. Одна задача AiCrew = один репозиторий; межрепозиторные задачи менеджер разбивает на подзадачи с зависимостями в DAG. | как в ТЗ |
| 3 | Синхронизация | Журнал операций: `client_id`, `operation_id`, `base_server_revision`, `client_seq`; порядок задаёт сервер (`server_revision`); при конфликте сохраняются обе версии. | как в ТЗ |
| 4 | Модель контента | `raw_content` отдельно от `structured_content` + `structured_from_revision`. | как в ТЗ |
| 5 | Execution | Сущности `ExecutionHost`, `Worker`, `Repository` (путь привязан к host). | как в ТЗ |
| 6 | Recovery | Lease + heartbeat. | как в ТЗ |
| 7 | Claude Code | **Подписка.** Headless-запуск `claude -p` на домашнем ПК от пользователя `ai_worker`. Конкретный способ авторизации и его условия фиксируются и проверяются на этапе 7.1. Лимиты подписки общие с вашей ручной работой в Claude, поэтому обязательны дневной лимит вызовов и `budget_policy` по лимитам. Оркестратор работает через абстракцию `AgentProvider`, переход на API-ключ не ломает систему. | подписка — решено Максимом |
| 8 | Веб-клиент | **Flutter Web**: максимум общего кода с mobile и desktop (пакет `shared/`). | согласовано |

Не входит в P0 (решается на этапе 3): выбор локальной БД и абстракция `LocalStorage`, схема PostgreSQL, бэкапы на VPS.
