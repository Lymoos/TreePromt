# Roblox UI/UX: ручная работа, а не ИИ-слоп

## 1. Порядок работы

1. **Задача игрока.** Одной фразой: что игрок должен понять или сделать за 2 секунды? Всё, что не помогает, убери.
2. **Иерархия.** Одно главное действие на экран. Остальное вторично по размеру, контрасту и положению.
3. **Дизайн-токены** (один модуль `UITheme`) до первой кнопки: цвета, радиусы, отступы, шрифты, тайминги. Никаких «магических» значений в коде экранов.
4. **Каркас на Layout-объектах**, затем стили, затем анимации, затем звук.
5. **Проверка** на трёх форм-факторах (см. п. 7) и во всех состояниях кнопок.

## 2. Что выдаёт ИИ-слоп (избегай)

- Фиолетово-синий градиент на всём подряд, неоновое свечение, стекло без причины.
- Всё скруглено одинаково (`UDim.new(0, 8)` везде), у всех элементов одинаковая тень.
- Эмодзи вместо иконок, случайные эмодзи в заголовках.
- Центрированный текст везде, одинаковые карточки сеткой без акцента.
- Дефолтный `SourceSans` / `Gotham` везде, один размер шрифта.
- Размеры в пикселях (`Offset`) на весь экран, панели, которые на телефоне перекрывают игру.
- Кнопка без hover/press/disabled-состояний; мгновенное появление окон.
- Лишние рамки: у каждого фрейма `UIStroke` + тень + градиент.

## 3. Признаки живого, «рукотворного» интерфейса

- **Характер.** Выбери мир игры (мультяшный, ретро, sci-fi, фэнтези) и делай форму, шрифт, иконки и звук из него. Интерфейс принадлежит игре, а не «универсальный».
- **Ограниченная палитра:** 1 основной цвет, 1 акцент (для главного действия и наград), нейтральные (3–4 тона фона/текста), семантика (успех/ошибка/предупреждение). Акцент занимает не более ~10% площади.
- **Тёмный не значит чёрный.** Фон — оттенок основного цвета (например `Color3.fromRGB(24, 27, 38)`), текст — не чистый белый (`235, 238, 245`).
- **Слои глубины:** фон < панель < карточка < активный элемент. Глубину задавай светлотой и тонкой нижней «ступенькой»/тенью, а не размытым свечением.
- **Небольшая асимметрия и несовершенство:** слегка наклонённый заголовок, значок-бейдж, выступающий за край карточки, разные радиусы у вложенных уровней (внутренний = внешний − отступ).
- **Ритм отступов** по сетке 4/8: 4, 8, 12, 16, 24, 32. Внутри группы меньше, между группами больше (близость = связь).
- **Типографика:** максимум 2 шрифта (заголовочный с характером + читаемый для текста). Шкала: 12 / 14 / 18 / 24 / 36. Вес и размер, а не цвет, строят иерархию. `RichText` для акцентов в цифрах.
- **Иконки** единого стиля (толщина линии, скругление, заливка). Не смешивай наборы.

## 4. Roblox-техника

### Раскладка
- Используй `UIListLayout`, `UIGridLayout`, `UIPadding`, `UIAspectRatioConstraint`, `UISizeConstraint`, `UITextSizeConstraint`, `UIScale`. Позиционируй вручную только оверлеи и бейджи.
- Крупные контейнеры — `Scale`, фиксированные мелкие элементы (иконки, высота строк) — `Offset`. Для плавающих элементов `AnchorPoint` + `Position` (напр. `0.5, 0.5`).
- Списки: `AutomaticSize = Y` + `ScrollingFrame.AutomaticCanvasSize = Y`; задай `ScrollBarThickness` (4–6) и стилизуй полосу.
- `ScreenGui.ResetOnSpawn = false` для постоянных интерфейсов; `IgnoreGuiInset = true` только для полноэкранного фона; `ZIndexBehavior = Sibling`, слои через порядок и `LayoutOrder`, а не через `ZIndex = 999`.

### Стиль
- `UICorner`: радиус из токенов (напр. 6 / 10 / 16); «пилюля» = `UDim.new(1, 0)`.
- `UIStroke`: 1–2 px, `ApplyStrokeMode = Border` для рамок панелей, `Contextual` для текста. Для читаемости текста на ярком фоне — обводка тёмным оттенком, а не чёрным.
- `UIGradient`: тонкий (разница светлоты 5–10%), угол 90°, для объёма кнопок. Не радужные.
- Тень — отдельный `ImageLabel` со слайсом (`ScaleType = Slice`) или смещённый тёмный `Frame` под кнопкой («3D-ступенька» 3–4 px).
- `ImageLabel` / `9-slice` для панелей с декоративной рамкой; `ResampleMode = Pixelated` для пиксель-арта.
- Шрифты: `Font.new(...)`/`FontFace` с нужным весом; проверяй кириллицу, если игра локализована.

### Анимации (TweenService)
- Тайминги: hover 0.12–0.18 с, нажатие 0.08 с, открытие окна 0.25–0.35 с, закрытие чуть быстрее открытия.
- Easing: вход — `Quad/Back Out`, выход — `Quad In`. Пружинистость (`Back`, `Elastic`) — дозированно, только для наград и поп-апов.
- Окно появляется: `UIScale` 0.92→1 + прозрачность `GroupTransparency` (через `CanvasGroup`) 1→0.
- Отменяй предыдущий твин перед запуском нового, храни ссылку. Не твини в `RenderStepped` вручную.
- Числа (валюта, XP) — плавный счётчик; награда — короткая подсветка + звук.
- Уважай настройку «уменьшить анимацию» в игре, если она есть: отключай тряску и пульсацию.

### Состояния кнопки (обязательны)
`Default` → `Hover` (светлее, +1–2 px подъём) → `Pressed` (темнее, смещение вниз на глубину ступеньки) → `Disabled` (десатурация + нет реакции) → `Loading`/`Success`/`Error` при серверных запросах. Для консоли и геймпада — отдельный `Selected` (`GuiService.SelectedObject`, видимый фокус).

## 5. UX-правила для Roblox

- **Мобильные — приоритет** (большинство аудитории). Цель касания не менее 44×44 px, лучше 48+. Отступы от краёв и «чёлки» (`GuiService:GetGuiInset()`, `ScreenInsets`). Учитывай, что по краям экрана уже стоят системные кнопки (чат, меню, прыжок/thumbstick).
- **HUD не загораживает мир.** Постоянный HUD — по краям и компактный; детали — по запросу. Центр экрана свободен.
- **Один модальный слой** за раз. Закрытие: кнопка ×, тап по затемнению, `Esc`/`B`. Окно не должно терять управление персонажем без необходимости.
- **Обратная связь на каждое действие**: звук, анимация, текст ошибки с причиной и выходом («Не хватает 50 монет — получить?»).
- **Подтверждение** только для необратимого и дорогого (покупка за Robux, удаление). Платные действия — явная цена и иконка валюты.
- **Онбординг** по ходу действия (подсветка, стрелка, короткая подсказка), а не стена текста. Подсказки можно пропустить.
- **Пустые и загрузочные состояния** продуманы: скелетон/спиннер, «пока ничего нет» с подсказкой, что сделать.
- **Читаемость:** контраст текста к фону ≥ 4.5:1, не передавай смысл одним цветом (добавь иконку/форму), строки короткие, числа с разделителями (`1 250`, `12.4K`).
- **Локализация:** запас по ширине 30–40%, `TextScaled` только с `UITextSizeConstraint`, лучше фиксированный размер и `TextWrapped`.
- **Магазины и монетизация:** честно показывай цену и содержимое; не используй тёмные паттерны (ложные таймеры, неотключаемые поп-апы), особенно для детской аудитории.

## 6. Структура кода

```
src/shared/UI/Theme.luau          -- токены (ReplicatedStorage)
src/client/UI/                    -- StarterPlayerScripts
  Components/Button, Panel, Tooltip, ProgressBar, Toast
  Screens/Shop, Inventory, Hud
  Controller.luau                 -- открытие/закрытие, один активный экран
```
- Компоненты — функции/классы `Create(props) -> Instance`, без логики игры. Данные приходят через сигналы/атрибуты/Remote с сервера; клиент UI ничему не доверяет и ничего не решает (валидация покупок и наград — на сервере).
- Интерфейс строится в коде из компонентов и живёт в репозитории (Rojo, см. скилл `roblox-luau`): то, что собрано только в Studio, не попадает в git и теряется. Готовые декоративные ассеты — файлами модели в репозитории, а не правками в Studio. Именуй объекты по роли (`CloseButton`, `PriceLabel`), а не `Frame2`.
- Очищай соединения (`Maid`/`Trove`/`:Destroy()`) при закрытии экрана.

## 7. Чек-лист перед сдачей

- [ ] Палитра ≤ 1 основной + 1 акцент + нейтральные; акцент только на главном.
- [ ] Все значения из токенов; сетка 4/8; радиусы осмысленны, не одинаковы.
- [ ] 2 шрифта максимум, шкала размеров, кириллица отображается.
- [ ] Проверено в эмуляторе: телефон (портрет и ландшафт), планшет, ПК 1080p, консоль/геймпад.
- [ ] Ничего не уходит под «чёлку» и системные кнопки; HUD не закрывает центр.
- [ ] У каждой кнопки есть hover / press / disabled / focus.
- [ ] Открытие/закрытие анимировано, твины отменяются, нет утечек.
- [ ] Контраст ≥ 4.5:1; смысл не только цветом.
- [ ] Есть пустое, загрузочное и ошибочное состояния.
- [ ] Экран можно «прочитать» за 2 секунды: понятно главное действие.
- [ ] Нет эмодзи-иконок, радужных градиентов, свечения без причины.

## 8. Как сдавать задачу в AiCrew

1. Код — в файлах репозитория (`src/...`), стиль и проверки как в `roblox-luau` (`--!strict`, `stylua --check .`, `selene .`).
2. Сначала токены (`Theme`), потом компоненты, потом экран; комментарии только там, где неочевидно.
3. Проверь экран в Roblox Studio через его MCP-сервер (профиль `roblox`): запусти игру, сними снимки на телефоне (портрет и ландшафт) и ПК, пройди состояния из чек-листа. Задачи с интерфейсом дополнительно смотрит Vision QA по снимкам.
4. В итоговом сообщении — цель экрана, палитра и шрифты (токены), иерархия контейнеров текстом, какие состояния реализованы и на каких устройствах проверено.
